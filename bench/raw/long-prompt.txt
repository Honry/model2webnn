Gated DeltaNet for one head (state S [dk, dv], per token: L2-normalised q, k, q scaled by dk^-0.5, `g = -exp(A_log) * softplus(a + dt_bias)` <= 0, `beta = sigmoid(b)`):     S <- exp(g) S ;  S <- S + k (beta (v - S^T k))^T ;  o = S^T q          (the conv: depthwise causal, kernel 4, silu, over the 8192 qkv channels)   unrolled (the trip count is static) and only the state travels from one to the next. The single non-matmul piece is `(I + A)^-1 [beta v | beta k exp(gc)]` for a strictly lower-triangular A,   which HF computes with a for loop over the rows. It is a **row-by-row substitution** here (`gated_delta.forward_substitution`, 16 dependent steps for ALL sub-chunks at once: everything that   does not depend on the state, i.e. the decay matrix, A, the substitution, `q k^T` and the decayed keys, is computed for all sub-chunks as a batch dimension; `gated_delta_batched`).   The shortcut `(I - A)(I + A^2)(I + A^4)...` is exact in theory but **explodes for nearly parallel keys** (repeated text): the powers of A grow like binomial coefficients before they cancel; a blocked   variant needs 8 x 8 activation matmuls, which the NPU compiler rejects.   [C+3, C+3] is a permutation matrix applied to `[3 state rows | C chunk rows]` that moves the pad rows in front of the state rows (the identity for a full chunk); the new conv state is then the last 3 rows.   `protocol.linear_prefill_controls` / `protocol.ts linearPrefillControls` build both. The states are zeroed at the start of every prompt. "Parallel" here is the algorithm, not a WebNN feature: a WebNN graph is a DAG of operators that the device runs in dependency order (the NPU is parallel *inside* an operator, e.g. a matmul). The Loop has a **dynamic trip count = the number of tokens** (prefill and decode use the same loop): every iteration takes one token (q_t, k_t, v_t, g_t, beta_t sliced along the token axis, `part_size 1`), the state [B, 32, 128, 128] is loop-carried and the body is the recurrent update written with elementwise operators and `ReduceSum` (no `MatMul`): `S * exp(g)`; `ReduceSum(S * k)`; `(v - that) * beta`; `S + k (x) delta` (`Unsqueeze` + `Multiply` + `Add`); `ReduceSum(S * q)` written into the output buffer with `ScatterUpdate`. There is no chunkwise-parallel form in it (it is the torch fallback `torch_recurrent_gated_delta_rule` traced as it is). That is fine for a GPU plugin that runs a Loop; WebNN has no loop operator, and a per-token dispatch of the decode graph would make a prompt of N tokens cost N decode steps. So the pointwise parts, the projections and the norms follow the OV graph; the recurrence and the conv do not, on purpose.
